# 快应用桌面运行时 · 架构原理

> 用 Tauri v2 把现有 `web-runtime` 包成 macOS / Windows 桌面运行时的整体设计、可行性与核心机制说明。
> 设计第一原则：**前端零改动** —— 复用 `quicktvui/packages/web-runtime/dist` 纯静态产物，只在外层加一层很薄的 Rust 后端（`desktop-runtime/src-tauri`）。

---

## 1. 一句话定义

桌面运行时 = **系统 WebView（macOS WKWebView / Windows WebView2）+ 一个原生外壳（Rust）**，把"在浏览器里跑的 web-runtime"搬进原生窗口。它不重写渲染引擎，只负责三件事：**加载 web-runtime 静态资源、把本地文件/远程包的字节喂进既有加载管线、把需要 OS 支撑的原生模块调用转给 Rust**。

---

## 2. 整体分层架构

```
┌────────────────────────────────────────────────────────────────────┐
│  桌面操作系统  macOS (WKWebView) / Windows (WebView2)                │
│                                                                        │
│  ┌──────────────────────────────────────────────────────────────┐   │
│  │  Tauri v2 外壳 (Rust · desktop-runtime/src-tauri)             │   │
│  │  • 窗口管理（16:9 比例锁定、全屏/最大化放行）                  │   │
│  │  • IPC Commands（薄一层原生能力）：                          │   │
│  │    load_local_app(path) / fetch_remote_zip(url,onProgress)    │   │
│  │    open_in_explorer(path) / system_info()                     │   │
│  │  • 插件：dialog · fs · shell（本地导入/外部打开/系统能力）   │   │
│  └───────────────┬───────────────────────────────┬──────────────┘   │
│                   │  tauri://localhost (prod)       │  invoke()       │
│                   │  http://localhost:1420 (dev)    │  ← 模块调用     │
│                   ▼                                ▼                  │
│  ┌──────────────────────────────────────────────────────────────┐   │
│  │  WebView 引擎  (WKWebView / WebView2，无需内嵌 Chromium)      │   │
│  │                                                                │   │
│  │  ┌────────────────────────────────────────────────────────┐  │   │
│  │  │  web-runtime (纯静态 dist，前端零改动)                 │  │   │
│  │  │                                                          │  │   │
│  │  │  loader.js  应用加载管线                                  │  │   │
│  │  │   • Phase 0: ZIP 虚拟文件系统 (IndexedDB)               │  │   │
│  │  │   • 入口探测: index.bundle→index.android.js→.bundle→.js │  │   │
│  │  │   • Proxy 拦截 appRegister 无侵入加载 Android bundle    │  │   │
│  │  │                                                          │  │   │
│  │  │  web-renderer (Vue 渲染 Android bundle 到浏览器)         │  │   │
│  │  │   • patches.js: hippyCallNatives → __WEB_MODULES__       │  │   │
│  │  │   • 事件回发通道: sendNativeEvent → app                  │  │   │
│  │  └───────────────────────┬────────────────────────────────┘  │   │
│  │                          │ 字节流注入（绕过 file:// CORS）     │   │
│  └──────────────────────────┼───────────────────────────────────┘   │
│                             ▼                                         │
│  快应用 bundle 三来源：  内置 resources/*.zip  │ 本地 sideload  │ 远程 zipUrl
└────────────────────────────────────────────────────────────────────┘
```

> 关键事实：**Tauri 用 `tauri://localhost` 自定义协议直接加载静态资源（prod）**，不依赖任何本地 HTTP server；dev 态用 `scripts/serve.mjs` 静态服务器经 `http://localhost:1420` 加载，仅为满足 HMR/调试便利。两种加载都指向同一份 `web-runtime/dist`，前端代码完全一致。

## 3. 为什么这件事可行（三个契合点）

| # | 现状特征 | 带来的机会 |
|---|---------|-----------|
| 1 | `web-runtime/dist` 是**纯静态产物**（`index.html` + `web-runtime.*.js` + 一个 `.wasm`），`index.html` 里 `window.__webpack_public_path__ = '/'` 正好对应 Tauri 根路径 | 可直接当 Tauri 前端，无需任何打包改造 |
| 2 | 应用加载是**数据驱动**的：`?bundle=` / `?zipUrl=` / 上传 ZIP → `loader.js` 用 **JSZip 解压 + IndexedDB 虚拟 FS 缓存** | 桌面端只需把"本地文件路径/远程 URL"换成"Rust 读到的字节流"喂进这条既有管线，**解压/缓存逻辑一行不用动** |
| 3 | 原生模块桥接已是 **JS 适配器**：`web-renderer/patches.js` 的 `hippyCallNatives → global.__WEB_MODULES__`（纯 JS 实现 DOM/IndexedDB/audio 等） | 桌面端只需给「确实需要 OS 支撑」的模块（文件选择、外部打开、系统信息、下载）加一个"检测 `window.__TAURI__` → 改走 `invoke()`"的分支，其余原样保留 |

## 4. 核心机制拆解

### 4.1 前端零改动：复用 dist 而非重写

- `src-tauri/tauri.conf.json` 的 `frontendDist` **直接指向** `../../quicktvui/packages/web-runtime/dist`（相对 `src-tauri` 目录）。
- 路径坑（已规避）：`frontendDist` 相对 `src-tauri`，而 `beforeDevCommand` 的 cwd 是项目根（`desktop-runtime`）。两者层级不同，所以 `scripts/serve.mjs` 改为**按脚本自身位置解析 dist**，命令只传端口不传脆弱的相对路径。

### 4.2 应用加载管线全量复用（loader.js）

`loader.js` 已经把"加载快应用"做成了与传输方式无关的统一管线：

1. **Phase 0 · ZIP 虚拟文件系统**：基于 IndexedDB（`ZIP_DB_NAME`），`saveZipToDB()` 把解压后的文件树缓存起来，实现离线可用。
2. **入口探测**：从解压结果里按优先级找入口 `index.bundle → index.android.js → index.{android,hippy}.js → .bundle → .js`。
3. **无侵入加载**：通过 **Proxy 拦截 `appRegister`** 实现，不修改 Android 原有 bundle 代码。
4. **三种来源统一归一到这条管线**：
   - `?bundle=` 本地路径
   - `?zipUrl=` 远程 ZIP（桌面端改为 Rust `reqwest` 拉字节回传，避开 CORS/CSP）
   - 上传 ZIP → JSZip 解压 → IndexedDB → 刷新页面

> 桌面端要做的不是"再写一套加载器"，而是**把字节流喂进既有管线**：本地导入 = Rust 读文件字节 → `invoke` 回传 → 走上传解压路径；内置资源 = 编译期打包进 `resources/*.zip` → 启动器列出 → 同样走解压路径。

### 4.3 原生模块桥接复用（patches.js）

桥接入口 `patchHippyCallNatives(engine)` 覆盖 `global.hippyCallNatives`，路由规则：

1. 部分模块有**显式分支**（如 `ESIJKAudioPlayerModule` / `ESSoundPoolAudioPlayerModule` / `AndroidFileModule` / `ESDownloadModule` / `DownloadApkModule` / `InstallApkModule`）直接调 JS 适配器或 `engine.modules`。
2. **通用回退**：`engine?.modules?.[moduleName] || global.__WEB_MODULES__?.[moduleName]` —— 命中则委派原生，未命中则报错。

桌面端的增量改造：**检测 `window.__TAURI__`**，仅把确需 OS 支撑的模块（文件选择、外部打开、系统信息、下载）的回退目标切换为 `invoke()`。纯 JS 适配器（DOM/IndexedDB/audio）原样保留，因为 WebView 里这些 API 本来就有。

### 4.4 桌面特有能力的注入（IPC 字节流）

Tauri 的 WebView 里 **`file://` 受 CORS 限制不可用**，所以不能让 loader 直接 `fetch('file://...')`。桌面端用 Rust 做"安全边界"：

- `load_local_app(path)`：Rust 读本地文件字节 → `invoke` 回传给前端 → 喂进 loader 的解压路径。
- `fetch_remote_zip(url, onProgress)`：Rust 用 `reqwest` 带进度拉远程 ZIP → 回传字节。比前端 `fetch` 更稳（避开 CORS/CSP）。
- `open_in_explorer(path)` / `system_info()`：文件系统与系统信息采集。

### 4.5 窗口比例锁定 TV 端 16:9

**Tauri v2 没有原生 aspect-ratio 锁定 API**（`WindowSizeConstraints` 在 v2 里只有 `min/maxWidth/Height` 标量字段，v1 的 `set_aspect_ratio` 已被移除）。实现方式：

- 在 `.setup()` 里给 main 窗口挂 `on_window_event`，监听 `WindowEvent::Resized`。
- 拖动缩放时按 16:9 把另一维钳回；带 **0.5px 阈值防抖动**（`set_size` 会再触发 Resized，校正后已落阈值内不再重设，避免死循环）。
- 以宽/高为基准取偏差更小的方向校正，缩放手感自然。
- **全屏/最大化放行**，否则与显示器分辨率打架；还原后自动回到 16:9。
- 实现必须用 `window.clone().on_window_event(...)`（`WebviewWindow` 是 Arc 包装，clone 廉价），否则 `move` 闭包 + 方法借用冲突报 `E0505`。

前端 `web-runtime` 自身强制 1920×1080 画布 + CSS 缩放，窗口锁 16:9 后正好铺满无黑边。

### 4.6 事件回发通道（已通，不动）

web 模块要把事件发回 app，统一用 `sendNativeEvent(eventName, data)`（底层走 `EventDispatcher.receiveNativeEvent`，app 端经 `ESApp.$on(eventName)` 接收）。这条桥已在 `ESIJKAudioPlayerModule` / `WebGLModule` / `CanvasModule` / `ESSoundPoolAudioPlayerModule` / `ESNetworkSpeedModule` / `ESPluginModule` 等模块验证可用。**桌面端新增发事件的模块直接 `sendNativeEvent` 即可，不必重新验证桥接。**

## 5. 一次「打开本地快应用」的完整数据流

```
用户点击「导入」(前端 UI)
   │  plugin-dialog 选文件
   ▼
Rust: load_local_app(path) 读字节
   │  invoke 回传 ArrayBuffer
   ▼
前端: 收到字节 → 复用 loader.js 的「上传解压」路径
   │  JSZip.loadAsync(bytes) → 入口探测 → saveZipToDB()
   ▼
IndexedDB 虚拟 FS 缓存（离线可用）
   │  Proxy 拦截 appRegister → 加载入口 bundle
   ▼
web-renderer (Vue) 渲染 Android bundle → WebView 显示
   │  用户交互触发原生模块调用
   ▼
patches.js: hippyCallNatives → 桌面相关模块 → invoke() → Rust
   │  事件回发
   ▼
sendNativeEvent → app (ESApp.$on)
```

整条链路里，**前端渲染与加载逻辑 100% 复用现有代码**，桌面端只在"字节入口"和"OS 相关模块"两处插桩。

## 6. 桌面 vs TV/Web 的差异对比

| 维度 | TV / Web 版 | 桌面运行时 (Tauri) |
|------|------------|-------------------|
| 渲染引擎 | 系统 WebView / 浏览器 | WKWebView(macOS) / WebView2(Windows) |
| 静态资源加载 | HTTP server 或 file:// | `tauri://localhost` 协议（无需 server） |
| 本地文件读取 | 受 CORS 限制 | Rust `load_local_app` 读字节注入 |
| 远程包 | 前端 `fetch` zipUrl | Rust `reqwest` 拉字节（避 CORS/CSP） |
| 原生模块 | JS 适配器 + 部分原生 | JS 适配器 + invoke() 到 Rust（OS 相关） |
| 窗口比例 | TV 强制 1920×1080 | 窗口锁 16:9（全屏/最大化放行） |
| 安装包体积 | — | ~5MB（不内嵌 Chromium） |

## 7. 关键约束与已踩坑

| 坑 | 现象 | 处置 |
|---|------|------|
| **图标必须 RGBA** | `generate_context!` 报 `icon 32x32.png is not RGBA` | `scripts/gen_icons.py` 输出 colortype=6（每像素加 alpha），IHDDR 第 25 字节须为 6 |
| **`on_window_event` 借用冲突** | 报 `E0505 cannot move out of window because it is borrowed` | 改用 `window.clone().on_window_event(move \|event\| {...})` |
| **`file://` 不可用** | WebView 里 `fetch('file://')` 被 CORS 拦 | 一律走 IPC 字节注入，不让 loader 直接读本地文件 |
| **CSP** | Tauri 默认 CSP 很严，远程 zipUrl 易失败 | dev 态 `security.csp: null`；远程包走 Rust 拉字节更稳（P4 再收紧 CSP） |
| **WebGL** | 3D 打砖块依赖 WebGL | WebView2 支持 WebGL，但需实机确认 GPU；SSAA/DPR 逻辑两端验证 |
| **窗口比例无原生锁** | Tauri v2 无 `set_aspect_ratio` | 监听 `Resized` 手动钳制（见 4.5） |
| **全局 Tauri CLI 是 v1** | 全局 `tauri` 是 v1.6.6，v2 项目不能用 | 用 `npm install` 装本地 `@tauri-apps/cli@2` |
| **headless 沙箱** | 本助手沙箱无 GUI 会话，窗口无法渲染 | 代码能完整编译运行；窗口在用户本机 macOS GUI 会话里弹出 |

## 8. 下一步（P1 +）

- **P1 加载**：离线内置 `resources/*.zip`（编译期打包几个游戏）+ 本地导入（dialog）+ 远程 `zipUrl`（Rust 下载）——三者全部喂进 `loader.js` 解压/IndexedDB 管线，前端不动。
- **P2 桥接**：审计 `__WEB_MODULES__` 全量，桌面相关模块接 Rust；`sendNativeEvent` 回发已通，不动。
- **P3 Windows**：`tauri build` 出 msi/exe；WebView2 处理（Windows 包不能在 macOS 交叉编译，需 Windows 跑或 GitHub Actions）。
- **P4 签名分发**：macOS Developer ID + 公证（dmg）；Windows 代码签名 + SmartScreen；`tauri-plugin-updater` 自动更新。
- **P5 打磨**：键盘映射（TV 遥控→方向键）、单实例、系统托盘。
